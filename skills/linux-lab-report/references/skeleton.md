# 模板段落编号蓝图

`scripts/labdocx.py` 用 `build_pmap()` 给 `assets/template.docx` 里的每个段落编号，编号规则是**按 body → tbl → tr → tc → p 的顺序深度优先遍历**。`TPL_INDEX` 里的数字就是这个编号。

这份文档说明每个编号对应哪个元素。改模板或改 `TPL_INDEX` 时读它。

## 怎么重新生成蓝图

模板改动后，用 skill 里的 dump 脚本重新导出：

```bash
python scripts/dump.py assets/template.docx skeleton.txt
```

输出的每行是 `<全局序号> <pPr摘要> :: <run内容>`。照着核对 `TPL_INDEX`。

## 编号规则

深度优先遍历 `document.xml` 的 body：

1. 遇到 `w:p` → 分配下一个序号
2. 遇到 `w:tbl` → 进入 `w:tr` → `w:tc` → 递归（所以表格单元格里的段落也会被编号）
3. 表格本身不占编号

因为正文全在**外层表格第 4 行第 1 个单元格**里，正文段落的编号从 28 开始（前面的 0–27 是抬头和模板表格的表头）。

## 生成时的操作顺序

`build_report()` 的顺序有讲究，改的时候注意依赖关系：

1. 改抬头、目的、设备、引言、两张前置表 —— 这些都是模板里已有的段落，直接改文字。
2. **先建好站点内容**，插到报错表标题（111）之前。
3. **再删掉占位站（99–110）**。
4. 改报错表、体会问题。

必须「先插后删」。如果先删占位站，锚点 111 的元素对象仍然有效（`pmap` 存的是元素引用，不是位置），但阅读代码的人容易搞错——而且如果将来把锚点改成占位站后面的某个元素，先删就会拿到已脱离文档树的元素。

> `pmap` 里的编号只在 `build_pmap()` 调用时正确。**一旦增删段落，编号就失效了**——所以生成过程中要用元素引用（`T['xxx']`），不要再按编号去 `pmap[n]` 取东西。

## 多段落元素的伸缩

实验目的、设备、体会问题在模板里各有 3 条 / 6 条 / 2 条槽位，但实际内容条数不定。
`siblings_from(el, n)` 按「块签名」认出这一款段落，把它伸缩到 n 条：

- **收边**：只吃和 `el` 同签名（`list_sig()`：pStyle + numPr + ind + jc）的后续段落。
  签名必须够宽——实验体会的问题既没有 pStyle 也没有 numPr，只有 `ind left=420`，
  只比 pStyle/numPr 的话它们的签名全是空的，等于没有边界，会一路吃过界把
  「教师签名：何康健」那一行改成问题。
- **清空多余槽位**：模板给 3 个目的槽位、只写 2 条时，必须把第 3 条删掉。所以
  循环是**一路收到底**再裁剪，而不是收够 n 就停——收够就停会把
  「【此处填写实验目的第 3 条…】」留在文档里。
- **不够就克隆**最后一条补上（克隆继承 numId，编号自然接得上）。

槽位被吃过界的症状：某一段的 `pPr` 突然换了样（编号丢了、华文中宋没了、缩进变了）。
槽位没清干净的信号：全文搜得到「【此处填写」。

站点标题后面那几条（命令行、提示）不是固定条数，所以不用 `siblings_from`，而是按 spec 逐条 clone 样板。
